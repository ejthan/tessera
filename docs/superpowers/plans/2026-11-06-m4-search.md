# M4 Search and Raw Console Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A search workbench with form and JSON modes, results with highlights, facets and groups, multi and union search, history, saved queries, presets and code export whose curl reproduces the response; a raw console that cannot leave its node; the full view of truncated log bodies; a command palette and `keymap.toml`.

**Architecture:** `tessera-client` gains `search.rs`, a private read flag for `POST /multi_search`, and raw requests with response headers. `tessera-core` gains `search/` (draft, results, facets, sort, export, history, saved, fuzzy), `raw.rs`, `openapi.rs`, `keymap.rs` and a budget for full bodies in `RequestLog`. `tessera-widgets` gains `BodyView` and `CompletionInput`. `tessera-app` gains a `SearchBackend` seam, `views/search/`, `views/console/`, `views/palette.rs`, and two new tab kinds. Four PRs, in order: A (Tasks 1–5), B (Tasks 6–9), C (Tasks 10–12), D (Tasks 13–14).

**Tech Stack:** Rust 2024, GPUI Kit 0.9.0 (gpui-pre 0.3.11), reqwest 0.13.5, tokio 1.54.1, serde_json 1.0.154 with `preserve_order`, wiremock 0.6.5, insta, toml 1.2.0.

**Spec:** [`docs/superpowers/specs/2026-11-06-m4-search-design.md`](../specs/2026-11-06-m4-search-design.md). Section numbers below (§4.3 …) refer to it. Read the section a task names before starting it.

## Global Constraints

- Every source file starts with `// SPDX-License-Identifier: GPL-3.0-or-later`.
- `tessera-client` and `tessera-core` never depend on GPUI. Direction: `app → widgets → core → client`.
- Direct dependencies are pinned exactly (`=x.y.z`) in the workspace `Cargo.toml`. The only new one in M4 is `toml = "=1.2.0"`, in Task 14.
- Never guess a GPUI or GPUI Kit API. Read the pinned source under `~/.cargo/registry/src/*/gpui-component-0.9.0`, `gpui-base-0.9.0`, `gpui-kit-0.9.0` and `gpui-pre-0.3.11` first. When a task names a file there, it was verified; anything else you need, verify the same way.
- Every UI string goes through `t!()`, same keys in `assets/locales/en.yml` and `de.yml`, under `search.*`, `console.*` or `palette.*`. The key-parity test stays green. `tessera-widgets` has its own `rust_i18n::i18n!`.
- No blocking I/O on the GPUI thread. Network calls go through the backend seam on the tokio runtime. File reads and writes go through `spawn_blocking` or the background executor. Parsing of responses happens in the tokio future, formatting of large text on the background executor.
- No key in logs, files, errors, `Debug` or `Display`. Redaction tests are never removed.
- Anything a user types or a server returns that ends up in a URL path, a query or a filter passes an allowlist first: `parse_path`, `param_key_ok`, the draft's key pattern, `facet_value_ok`, `addressable`.
- A running write must not be aborted by dropping a view: spawn it detached as `crates/tessera-app/src/views/documents/bulk.rs` does (`run(window, cx).detach()`, line 397, and the job helper at line 417). A read may be aborted.
- File saves are owned by `AppState`, each awaiting the previous one, on the background executor, flushed with `cx.on_app_quit`, like `views_save_task`. A view never owns a save.
- Destructive flows confirm first and cancelling changes nothing. Medium: `tessera_widgets::confirm::open`. High: `tessera_widgets::confirm_danger::open`. Default focus is never on the destructive button.
- A 200 can hide a failure. Check `/multi_search` errors and import lines (§4.3, §5.7).
- After every task: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --workspace`. No commit with a failing check.
- Commits: `git commit -s`, message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Dev Typesense: `TYPESENSE_PORT=18108 docker compose -f dev/docker-compose.yml up -d`, key `xyz`, live tests with `TESSERA_IT_URL=http://localhost:18108 TESSERA_IT_KEY=xyz cargo test -p tessera-client --test live -- --ignored`. ## Review Focus

1. A console path such as `//evil.example/x`, `http://evil.example/`, `http:x`, `\\evil`, `%2e%2e/keys` or `collections/..%2f..%2fkeys` must never reach another host or another resource. Tests in Tasks 10 and 11.
2. A read-only client must pass `search` and `multi_search` and refuse `raw` with POST, also to `/multi_search`. Tests in Tasks 1 and 10.
3. Export must produce the request the client sends, from the same route. Acceptance test in Task 9.
4. `enable_analytics: false` must be in a new draft, visible in JSON mode, and in what runs. Test in Task 2.
5. A facet value with a backslash, a backtick or a lone `*` must not reach `filter_by`. Test in Task 3.
6. Federated results must show one search's error without losing the others. Test in Task 6.
7. History must never hold a key parameter or an `api_key` value, and an entry with a mask must not be sent. Tests in Tasks 7 and 11.
8. A console write must survive closing its tab; cancelling a confirmation must send nothing. Test in Task 11.
9. A corrupt `saved_queries.json` must not be overwritten. Test in Task 7.
10. Palette actions must run in the focus the palette opened from. Test in Task 13.
