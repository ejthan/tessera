# Changelog

## [Unreleased]

### Added

- Log files: Tessera writes `tessera.log.YYYY-MM-DD` to the `logs` folder of its data directory, a new file each day and the last 7 kept, and goes on with stderr alone if the folder cannot be made. Every line, on stderr too, passes a mask for keys in URLs, JSON pairs, header lines and log fields, and a test scans the file and stderr of a whole session at `RUST_LOG=trace` for keys and request bodies. Each start logs `ready in N ms` at the first frame. New dependency `tracing-appender` 0.2.5.
- Restore: ⌘2 in the Backup tab, or Choose… (⌘O) with a `.tar.zst` or a folder, unpacks, checks every file, reads the backup and compares it with the server, each stage with Stop and each failure in full under the button. One row per collection, set, stopword set and alias says New, Same, Differs or Blocked with the reason, and a collection whose provider keys were left out says that it stays blocked, that Tessera cannot take the keys, and which two files to use by hand. Replace what differs is off by default. Start (⌘↩) asks with the counts, and asks for the profile's name on prod or when something is replaced; a read-only connection unlocks first. The run is a job, and the tab shows each row's result and what to delete before a retry. `docs/building.md` lists the on-screen checks of M8.
- Backup tab: the Backup row in the sidebar (⌥⌘B / Ctrl+Alt+B) lists the collections with their counts and an All box, offers a folder or a `.tar.zst`, says what a backup holds and leaves out, and warns about unstored fields, left-out keys, dictionaries and references outside the selection. Start (⌘↩) asks where to, refuses a name that exists or is a link, and needs no unlock. The run is a job: the Jobs row shows the step, the collection and its numbers, it goes on with the tab closed, and it stops like an import. Temp directories of a crashed backup go after a day, like reindex copies.
- A restore writes an alias that a reference needs before the dependent's import, so a reference through an alias can be restored, and a failed import names the first reason. A backup blanks secret-named values in set items as it does in schemas and warns about them, a blank in `metadata` no longer blocks a restore, and a backup that a restore could not read is refused while it is written. Nothing can be loaded from a folder that `verify` did not pass. What waits for a reference cycle comes after it, a name listed twice no longer reads as one that appeared on the server, a stop after the last batch reads as a stop, and a stale `.part` next to an archive target stops the run before the first export.
- The Ops tab reads each node's role itself every 2 seconds while it shows, so the picker and the vote button stay true with the Overview tab closed. Nodes on one host with different paths are told apart and picked by position. A lost connection shows under the row, and `/.` is refused as a snapshot path. Edit connection… on the transport banner has a shortcut, ⌥⌘X / Ctrl+Alt+X, and deleting a set item is red. `THIRD_PARTY_NOTICES.md` carries the BSD-3-Clause notices of zstd.
- Backup and restore engines in `tessera-core`: a backup writes schemas, all documents, attached sets, stopwords and aliases to a folder or `.tar.zst`, private to the user, and holds no provider key: credentials under `model_config`, unknown keys there too, and secret-named keys anywhere in a schema are blanked and counted. A restore recomputes its plan before the first write, creates what is missing with referenced collections first and aliases last, never writes to an existing collection or a name an alias holds, blocks a collection with blanked keys, a required unstored field or the mask, replaces what differs only when asked, and stops at the first failure with a list of what to delete before a retry.
- The backup format in `tessera-core`: a checked manifest with a size and SHA-256 per file, `.tar.zst` packing with private files, and an unpack that reads raw entries and allows exact paths, regular files and the declared size only, so traversal, links, devices, long-name entries and a decompression bomb are refused. New dependencies `tar` 0.4.46 and `zstd` 0.14.3, which bundles the zstd C sources.
- A banner above every tab of a connection says when it sends `http://` to a remote host or accepts any certificate. It has no close control, and Edit connection… opens the profile. Every button that deletes server data or a saved query is now red.
- An AI search keeps no response body in the request log, since a provider's error can echo a key, and the test panel still shows the error in full. Esc no longer closes the stemming import form while an import runs, so a failure stays visible. An unreadable chat answer shows both errors. The AI form says that a namespace change leaves the old URL on the server.
- Ops tab: the Ops row in the sidebar (⌥⌘0 / Ctrl+Alt+0) runs snapshot (⌘1 / Ctrl+1), compact (⌘2 / Ctrl+2), clear cache (⌘3 / Ctrl+3), leader vote (⌘4 / Ctrl+4) and one runtime config key (⌘S / Ctrl+S) on the node picked there, each under its row with the node and the time. - Operations in `tessera-core`: the snapshot path check, the closed list of seven runtime config keys with their value check, and the confirmation each operation needs. `POST /config` from the console now asks first, and asks for the typed word on prod, because it reaches `skip-writes`.

A body that says `success: false` is an error with its text, except on a vote, where it is the answer. Every design assumption about these calls was measured on 30.0 and 30.2.

- `cargo xtask nf3` measures the memory of a real import of 1,000,000 documents in any format on a 2-worker runtime with a request log, plus a run stopped half way, adds the RSS of the app's window from the smoke start, and fails at 300 MB. It runs every night and uses throwaway collections.
- Export pipeline: `tessera-core` writes a collection, a filter or a selection of ids to JSON Lines, a JSON array or CSV as it streams, through a part file beside the target that replaces it only when the export is complete, so stopping or failing leaves an existing file as it was. CSV takes its columns from the first 1,000 documents, with nested keys as `a.b`, `id` first and arrays as JSON, and counts the values it leaves out: keys a later document adds, or a key that flattens onto another. Cells stay verbatim, so a spreadsheet may run one as a formula. An export of nothing leaves an existing file alone, a file keeps its permissions and a symbolic link is refused. Field names that cannot be expressed in a request are refused before anything is sent.
- Import pipeline: `tessera-core` reads a source in a background thread and sends it batch by batch, 1,000 documents or 16 MiB at most, with no more than three batches in memory. Every document ends up imported, failed or unconfirmed: answers pair with the sent lines by position, a report keeps the first 1,000 failures and spools all of them to a private temporary file that saves as a report or as the failed lines, and the id in a report row comes from the line itself, because the server echoes the previous id on a line it cannot parse. Stop starts nothing new and waits for the batch in flight, a second stop drops it and calls it unconfirmed, a busy server (503) is retried five times, a batch the server refused counts as failed and one that ended in a 5xx or a broken connection as unconfirmed, saved reports are private to the user, a line that is not UTF-8 is saved so that it cannot be imported by accident, and `num_documents` is compared after the run.
- Import preview and schema inference: `tessera-core` reads the first 1,000 rows of a file and proposes a schema (`int64` for integers, `float` when they mix with decimals, `string` with a note where types disagree, optional for keys that are sometimes missing, `enable_nested_fields` for objects, never `geopoint` on its own), skips keys the server would mishandle, and previews the first 20 rows checked against a schema with an estimate of how many documents the file holds.
- Import and export readers: `tessera-core` reads JSON Lines, a JSON array or CSV as a stream of documents, detects the format from the name and first bytes, and never lets a line that is not UTF-8 or a record over 32 MiB reach the server, a stray CSV quote included. CSV cells follow the field types of the schema, a dotted header nests, and an empty cell leaves the key out.
- Export groundwork: the client streams `documents/export` line by line with no total deadline, only a 120 s limit on silence, and logs one request per stream with its size, `cancelled` when it was dropped early. A line over 256 MiB or a body that breaks off is an error.
- Import groundwork: the client sends one batch of documents to `documents/import` with an explicit action and `dirty_values` and returns one result per line, a line it cannot decode kept as a failure. The request log keeps no bodies of such a batch, says so in its detail and offers no curl command for it.
- Configurable shortcuts: `keymap.toml` in the config directory adds, replaces or, with no action, removes key bindings, and every control shows the chord in force. A bad entry is skipped and a file that does not parse changes nothing; both are named above the tabs. `escape` cannot be bound, so a dialog can always be left.
- Command palette and quick switch: ⌘K / Ctrl+K lists what the focused view can do now, the collections of open connections, the saved queries of the selected connection and the connections, ranked by a fuzzy match, each with its shortcut and environment. ⌘P / Ctrl+P lists collections only. An action runs in the focus the palette opened from, with the same unlock and confirmation as its control, and a control that is disabled is not listed.
- Full bodies in the request log: a body cut at 1 MiB keeps its whole text up to 32 MiB, 64 MiB over all entries, and ⇧⌘B / Ctrl+Shift+B or Show full opens it masked in a dialog named after the connection, in chunks of 512 KiB, the most the editor draws without holding a frame, with Previous and Next (⌥⌘[ / ⌥⌘], Ctrl+Alt+[ / ]) and Copy all. A body over 32 MiB says it was too large to keep. Once the log has let go of the text, the entry says so.
- Raw console: ⇧⌘Y / Ctrl+Shift+Y or the sidebar opens a Console tab per connection for any request. The path completes from the API and the collections, ⇧⌘A / Ctrl+Shift+A adds a query row, and a body is JSON, text or, with ⌘O / Ctrl+O, a file of up to 64 MiB. ⌘↩ / Ctrl+↩ sends: a path that could leave the node, a parameter that holds a key and a masked body are refused inline, a write unlocks a read-only connection first, and a dangerous request asks, by typing the name for a deleted collection and on prod. A write goes on when the tab closes. The answer shows masked until ⌥⌘K / Ctrl+Alt+K, with status, headers and a warning when a 200 hides failed import lines or searches, and the console keeps at most 32 MiB of an answer and says when it cut one. ⇧⌘H / Ctrl+Shift+H lists past requests with favorites (⌘D / Ctrl+D) first, and ⌥⌘U / Ctrl+Alt+U copies the request as curl.
- Raw requests groundwork: the client sends any request once to the active node and returns status, headers and body, `tessera-core` validates the path against an allowlist and rates the danger of a request, and neither a path that names another host nor one that climbs out of its place can leave the app with the key, however it is spelled.
- Export a search: ⌥⌘E / Ctrl+Alt+E copies it as curl, JavaScript, Python, Rust (reqwest) or a URL, and ⌥⌘U / Ctrl+Alt+U as curl directly. The code is the request the client sends, a long search by `POST`, which has no URL, and it reads the key from `TYPESENSE_API_KEY`, so no export holds a key.
- Search history, saved queries and presets: History (⇧⌘H / Ctrl+Shift+H) lists the searches of a connection, recording a run you start at once and an instant run after it stood for 2 s, and never one that failed or a parameter that holds a key. Saved (⌘O / Ctrl+O) lists the saved queries of the active collection, or of all, by name and tag, and ⌘⌫ / Ctrl+Backspace deletes one after asking. Save (⌘S / Ctrl+S) takes a name and tags and asks before replacing. Presets (⌥⌘P / Ctrl+Alt+P) lists the server's presets; a pick becomes one draft per search, and Save as preset asks before replacing and unlocks a read-only connection first. Enter loads a row into the drafts and runs nothing.
- Multi and union search: the Search tab holds up to 50 searches in tabs. ⌘T / Ctrl+T adds a copy of the active one, ⇧⌘W / Ctrl+Shift+W removes it and ⌥⌘← / ⌥⌘→ (Ctrl+Alt+Left / Right) switch. Several searches run as one `multi_search`, also with instant search, with one result tab per search, so one search's error stays on its tab. Union (⇧⌘M / Ctrl+Shift+M) merges them into one list that shows each hit's collection, takes its page from the first search, says that `found` is approximate, because it counts before duplicates and moves with the page, and ends at the first short page.
- Search history and saved queries groundwork: `history.jsonl` keeps the last 500 searches and 500 console requests per kind with secrets masked, `saved_queries.json` keeps saved queries and favorites and is left alone when it is corrupt or newer, and temporary connections write neither.

- Delete and update by query: ⇧⌘K / Ctrl+Shift+K and ⇧⌘U / Ctrl+Shift+U open a dialog with a filter, starting from the table's, and a live count, with the fields to set for an update. An update that reaches fewer documents than it counted stays open as a warning, since the server skips values that do not fit without an error.

### Fixed

- The inspector and the update by query dialog mark a numeric string for a numeric field as an error instead of a warning: without `dirty_values` the server refuses `"12"` for an `int32`, so a warning hid a save that would fail. The import preview keeps the warning, because an import coerces by default.
- Document pages ignore curation sets, so a wildcard rule cannot hide or add rows in the browser and the found count matches what a delete or update by query reaches.
- Embedding credentials (`api_key` and similar) are masked in the schema view, the request log and "Copy as curl".
- A key that may read collections but not aliases still lists its collections; the list, the schema view and the delete dialog say inline that the aliases could not be loaded and why.
- A long truncate or delete no longer blocks the window: "Stop waiting" closes its dialog while the server keeps going, and the list reloads when it is done. A schema change, truncate or delete that hits the 30-minute timeout is not retried on another node and says the server may still be applying it.
- On read-only connections, the write controls (New collection, Edit schema, Clone, Truncate, Delete) show the lock until writes are unlocked.

### Changed

- The release profile aborts on panic (`panic = "abort"`), which keeps the Linux binary under the 40 MB limit (NF5).
- Profiles are stored in `connections.json` without keys; keys are stored in the OS keychain.
- The live tests use `http://localhost:18108` by default instead of port 8108. The dev server still starts on 8108 unless `TYPESENSE_PORT` is set.
