# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Export documents: ⇧⌘X / Ctrl+Shift+X or Export in a collection's documents opens a dialog for the whole collection, the applied filter or the ticked rows, with a count that follows the filter after a pause. All fields, only some or all but some can be picked, and the file is JSON Lines, a JSON array or CSV. Start asks where to save and the export runs as a job; it reads only, so it needs no unlock. A finished export says when it wrote fewer documents than counted, or left CSV values out, and the CSV format notes that a spreadsheet may run a cell starting with = as a formula.
- Import into a new collection, with confirmation: New collection… in the import dialog proposes a name from the file and a schema from its first 1,000 rows, with notes where that is a guess and Use geopoint where a pair may be one. Edit schema… opens the schema form on top, whose Use schema sends nothing, so cancelling the dialog leaves the server as it was; the collection is created when the import starts, and a failed create stays in the dialog. Start confirms by what is at stake: `create` asks only on prod, `upsert`, `update` and `emplace` always, and they need the collection's name typed on prod or above 1,000 estimated documents.
- Import documents: ⇧⌘I / Ctrl+Shift+I or Import in the collections list and a collection's documents opens a dialog for a file, chosen with ⌘O / Ctrl+O or dropped onto the dialog or the view, or the clipboard up to 16 MiB with ⇧⌘V / Ctrl+Shift+V. The format is detected and can be overridden, CSV with its delimiter and header row. The first 20 rows show checked against the target's schema, with an estimate of the documents, and a line that cannot be sent says why. Action, dirty values and batch size are chosen here, ⌘↩ / Ctrl+↩ starts, and the job goes on in the Jobs tab. After saving failed lines, Import this file brings them back. On a read-only connection the dialog says so and Start asks to unlock.
- Jobs panel: imports and exports run as jobs in a Jobs tab beside the request log, opened with ⇧⌘J / Ctrl+Shift+J, and keep running when their dialog or tab closes or the connection disconnects. A row shows the connection and environment, a bar when the total is known, documents, rate, ETA and errors. ⌘. / Ctrl+. cancels after the current batch, then ⌥⌘. / Ctrl+Alt+. stops waiting for it. A finished import shows imported, failed and not confirmed, warns when the document count does not fit, lists the first 1,000 failures, and saves the report (⌘S / Ctrl+S) or the failed lines (⇧⌘S / Ctrl+Shift+S). ⌘⌫ / Ctrl+Backspace dismisses a finished job and asks first when that loses an unsaved report. The status bar counts running jobs, and a job that ends while the tab is hidden shows a toast.
- `cargo xtask nf3` measures the memory of a real import of 1,000,000 documents in any format on a 2-worker runtime with a request log, plus a run stopped half way, adds the RSS of the app's window from the smoke start, and fails at 300 MB. It runs every night and uses throwaway collections.
- Export pipeline: `tessera-core` writes a collection, a filter or a selection of ids to JSON Lines, a JSON array or CSV as it streams, through a part file beside the target that replaces it only when the export is complete, so stopping or failing leaves an existing file as it was. CSV takes its columns from the first 1,000 documents, with nested keys as `a.b`, `id` first and arrays as JSON, and counts the values it leaves out: keys a later document adds, or a key that flattens onto another. Cells stay verbatim, so a spreadsheet may run one as a formula. An export of nothing leaves an existing file alone, a file keeps its permissions and a symbolic link is refused. Field names that cannot be expressed in a request are refused before anything is sent.
- Import pipeline: `tessera-core` reads a source in a background thread and sends it batch by batch, 1,000 documents or 16 MiB at most, with no more than three batches in memory. Every document ends up imported, failed or unconfirmed: answers pair with the sent lines by position, a report keeps the first 1,000 failures and spools all of them to a private temporary file that saves as a report or as the failed lines, and the id in a report row comes from the line itself, because the server echoes the previous id on a line it cannot parse. Stop starts nothing new and waits for the batch in flight, a second stop drops it and calls it unconfirmed, a busy server (503) is retried five times, a batch the server refused counts as failed and one that ended in a 5xx or a broken connection as unconfirmed, saved reports are private to the user, a line that is not UTF-8 is saved so that it cannot be imported by accident, and `num_documents` is compared after the run.
- Import preview and schema inference: `tessera-core` reads the first 1,000 rows of a file and proposes a schema (`int64` for integers, `float` when they mix with decimals, `string` with a note where types disagree, optional for keys that are sometimes missing, `enable_nested_fields` for objects, never `geopoint` on its own), skips keys the server would mishandle, and previews the first 20 rows checked against a schema with an estimate of how many documents the file holds.
- Import and export readers: `tessera-core` reads JSON Lines, a JSON array or CSV as a stream of documents, detects the format from the name and first bytes, and never lets a line that is not UTF-8 or a record over 32 MiB reach the server, a stray CSV quote included. CSV cells follow the field types of the schema, a dotted header nests, and an empty cell leaves the key out.
- Export groundwork: the client streams `documents/export` line by line with no total deadline, only a 120 s limit on silence, and logs one request per stream with its size, `cancelled` when it was dropped early. A line over 256 MiB or a body that breaks off is an error.
- Import groundwork: the client sends one batch of documents to `documents/import` with an explicit action and `dirty_values` and returns one result per line, a line it cannot decode kept as a failure. The request log keeps no bodies of such a batch, says so in its detail and offers no curl command for it.
- Configurable shortcuts: `keymap.toml` in the config directory adds, replaces or, with no action, removes key bindings, and every control shows the chord in force. A bad entry is skipped and a file that does not parse changes nothing; both are named above the tabs. `escape` cannot be bound, so a dialog can always be left.
- Command palette and quick switch: ⌘K / Ctrl+K lists what the focused view can do now, the collections of open connections, the saved queries of the selected connection and the connections, ranked by a fuzzy match, each with its shortcut and environment. ⌘P / Ctrl+P lists collections only. An action runs in the focus the palette opened from, with the same unlock and confirmation as its control, and a control that is disabled is not listed.
- Full bodies in the request log: a body cut at 1 MiB keeps its whole text up to 32 MiB, 64 MiB over all entries, and ⇧⌘B / Ctrl+Shift+B or Show full opens it masked in a dialog named after the connection, in chunks of 512 KiB, the most the editor draws without holding a frame, with Previous and Next (⌥⌘[ / ⌥⌘], Ctrl+Alt+[ / ]) and Copy all. A body over 32 MiB says it was too large to keep. Once the log has let go of the text, the entry says so.
- Raw console: ⇧⌘Y / Ctrl+Shift+Y or the sidebar opens a Console tab per connection for any request. The path completes from the API and the collections, ⇧⌘A / Ctrl+Shift+A adds a query row, and a body is JSON, text or, with ⌘O / Ctrl+O, a file of up to 64 MiB. ⌘↩ / Ctrl+↩ sends: a path that could leave the node, a parameter that holds a key and a masked body are refused inline, a write unlocks a read-only connection first, and a dangerous request asks, by typing the name for a deleted collection and on prod. A write goes on when the tab closes. The answer shows masked until ⌥⌘K / Ctrl+Alt+K, with status, headers and a warning when a 200 hides failed import lines or searches, and the console keeps at most 32 MiB of an answer and says when it cut one. ⇧⌘H / Ctrl+Shift+H lists past requests with favorites (⌘D / Ctrl+D) first, and ⌥⌘U / Ctrl+Alt+U copies the request as curl.
- Raw requests groundwork: the client sends any request once to the active node and returns status, headers and body, `tessera-core` validates the path against an allowlist and rates the danger of a request, and neither a path that names another host nor one that climbs out of its place can leave the app with the key, however it is spelled.
- Export a search: ⌥⌘E / Ctrl+Alt+E copies it as curl, JavaScript, Python, Rust (reqwest) or a URL, and ⌥⌘U / Ctrl+Alt+U as curl directly. The code is the request the client sends, a long search by `POST`, which has no URL, and it reads the key from `TYPESENSE_API_KEY`, so no export holds a key.
- Search history, saved queries and presets: History (⇧⌘H / Ctrl+Shift+H) lists the searches of a connection, recording a run you start at once and an instant run after it stood for 2 s, and never one that failed or a parameter that holds a key. Saved (⌘O / Ctrl+O) lists the saved queries of the active collection, or of all, by name and tag, and ⌘⌫ / Ctrl+Backspace deletes one after asking. Save (⌘S / Ctrl+S) takes a name and tags and asks before replacing. Presets (⌥⌘P / Ctrl+Alt+P) lists the server's presets; a pick becomes one draft per search, and Save as preset asks before replacing and unlocks a read-only connection first. Enter loads a row into the drafts and runs nothing.
- Multi and union search: the Search tab holds up to 50 searches in tabs. ⌘T / Ctrl+T adds a copy of the active one, ⇧⌘W / Ctrl+Shift+W removes it and ⌥⌘← / ⌥⌘→ (Ctrl+Alt+Left / Right) switch. Several searches run as one `multi_search`, also with instant search, with one result tab per search, so one search's error stays on its tab. Union (⇧⌘M / Ctrl+Shift+M) merges them into one list that shows each hit's collection, takes its page from the first search, says that `found` is approximate, because it counts before duplicates and moves with the page, and ends at the first short page.
- Search history and saved queries groundwork: `history.jsonl` keeps the last 500 searches and 500 console requests per kind with secrets masked, `saved_queries.json` keeps saved queries and favorites and is left alone when it is corrupt or newer, and temporary connections write neither.
- Search results: the hit list shows ids, scores and highlighted matches, group headings for `group_by` and a curated marker; Up and Down or a click show the document and its `text_match_info` beside the list. The facet panel writes a checked value into `filter_by` and runs, a value a filter cannot hold stays disabled with a note, and Previous and Next (⌥⌘↑ / ⌥⌘↓, Ctrl+Alt+Up / Down) write `page` and run.
- Search tab: each connection gets a Search tab, opened from the sidebar or with ⇧⌘E / Ctrl+Shift+E, that edits a search as a form or as JSON (⌘1 / ⌘2, Ctrl+1 / Ctrl+2) over the same parameters, with `query_by` chips that drag and move by keyboard, an Add condition row and sort rows. ⌘↩ / Ctrl+↩ runs it; instant search (⌥⌘L / Ctrl+Alt+L) runs 150 ms after the last change, cancels the query before it and is off by default on prod, and a query that calls a model waits for Run. A new search sends `enable_analytics=false`. Errors show in full over the dimmed result, and the Raw tab (⌘4 / Ctrl+4) shows the response, pretty, highlighted up to 32 KiB, and in chunks of 512 KiB with Previous, Next and Copy all above that.
- Long document filters now work: a `filter_by` over 4,000 bytes, which the server refuses in a URL, is sent as a search in the request body, for the document table, the count and the delete and update dialogs.
- Document browser: a collection tab opens on its documents, with ⌘1 / Ctrl+1 for documents and ⌘2 / Ctrl+2 for the schema. The table spans all matching documents and loads pages as they scroll into view, holding at most 20 in memory; a click on a column header or ⌘⇧S / Ctrl+Shift+S on the selected cell sorts by that column on the server, and the old rows stay until the answer arrives. The status line shows the found and total counts, the search time and the sort. Keys seen in documents but not in the schema get their own column, and vector fields are left out of the pages.
- Document columns: a Columns popover (⌘⇧O / Ctrl+Shift+O) hides, shows and pins columns and resets them; ⌘⇧P / Ctrl+Shift+P pins the selected cell's column and ⌘⇧← / ⌘⇧→ (Ctrl+Shift+←/→) narrow or widen it by 20 px. Dragging a column edge works too. Hidden, pinned and sized columns are kept per connection and collection in `document_views.json` and survive reloads; a failed save is shown above the table.
- Document filter: a `filter_by` bar above the table with completion of fields, operators, `true` and `false`, and values of facet fields from the server. Enter picks from an open menu and otherwise applies the filter; no menu opens after a finished condition, ⌘F / Ctrl+F focuses the bar and ⇧⌘F / Ctrl+Shift+F clears it. A filter the server refuses shows its message in full under the bar while the old rows stay dimmed.
- Document inspector: ⌘I / Ctrl+I, Enter or a double click opens a JSON editor beside the table with the whole document, vector fields included, and it follows the selected row. ⌘G / Ctrl+G goes to a document by id, and an id that is not found shows next to the input.
- Copy documents: ⌘C / Ctrl+C copies the selected cell's whole value and ⌥⌘C / Ctrl+Alt+C the row as pretty JSON, also from the Copy menu or a right click on a cell.
- Copy a selection: the ticked rows, or the selected row, as JSONL (⌥⌘J / Ctrl+Alt+J) or as CSV of the visible columns (⌥⌘S / Ctrl+Alt+S), and a curl command (⌥⌘U / Ctrl+Alt+U) for the selected document or, with no row selected, for the current search. The key in the command is always `$TYPESENSE_API_KEY`. The three entries are also in the Copy menu and the right-click menu; a failure shows above the table.
- Edit documents: the inspector saves through a review (⌘↩ / Ctrl+↩) with a diff and the exact request body, as a PATCH or, with ⇧⌘M / Ctrl+Shift+M, as an upsert. The document is fetched again first, and a change on the server shows as a warning with the diff against it. The editor marks values that do not fit the schema and lists them underneath; ⇧⌘R / Ctrl+Shift+R reverts. Closing the inspector, ⌘W / Ctrl+W and Go to ID ask before they drop unsaved changes, and a tab with unsaved changes hides its close button; disconnecting or quitting drops them without asking.
- Select and delete documents: a checkbox per row, Shift+click or Shift+Space for a range of loaded rows, Space to tick the selected cell's row, ⌘A / Ctrl+A for the loaded rows and Esc to clear, up to 1,000 rows. A new filter or sort clears the selection. ⌘⌫ / Ctrl+Backspace deletes the ticked rows or the selected cell's row after a confirmation, which asks for the collection name above 1,000 documents or on prod; a failure stops the run and says how many went, and unsaved changes to a deleted row are named in the confirmation.
- Delete and update by query: ⇧⌘K / Ctrl+Shift+K and ⇧⌘U / Ctrl+Shift+U open a dialog with a filter, starting from the table's, and a live count, with the fields to set for an update. A blank filter, `*` and `id:*` are refused before anything is sent. Continue counts again and asks, by name above 1,000 documents or on prod. An update that reaches fewer documents than it counted stays open as a warning, since the server skips values that do not fit without an error.
- New document: ⇧⌘N / Ctrl+Shift+N opens a template built from the schema, ⌘↩ / Ctrl+↩ creates it, and a refusal stays inline with the draft kept.
- The empty documents view links the Typesense docs and, on a local connection, names `cargo xtask seed`.
- `--features frame-overlay` adds a frame-time overlay to the documents view, cycled with ⌘⌥F / Ctrl+Alt+F.
- Document browser groundwork: columns from the schema (vector fields left out), a page cache with previews built off the UI thread, and per-collection column preferences in `document_views.json`.
- `cargo xtask seed` also creates `products`, 200,000 documents with a nested `dimensions` object, for testing the document browser.
- Connect to a Typesense server by URL and API key and see its version, Raft role and health.
- Welcome screen with the Docker command for a local Typesense server.
- Errors from the server are shown in full inside the connect dialog.
- English and German UI, chosen from the system language.
- Connection dialog for new and edited profiles: name, color, environment, cluster nodes, read-only, timeout and retries. Test tells an admin key from a restricted one, keys go to the system keychain, and a keychain failure offers "Use for this session only".
- Delete a saved profile (⌘⌫ / Ctrl+Backspace) after a confirmation that removes its stored key too; import profiles from a typesense-dashboard `config.json` with a preview; export profiles as JSON without keys; reopen the last connection at startup; save a connection from flags or environment variables as a profile.

Polling pauses with Space and runs every 2, 5, 10 or 30 s; ⌘R / Ctrl+R reloads the collections. Every node is polled on its own loop and retried with a backoff of 5 s up to 30 s. The status bar follows the active node (role, host, latency of its last poll), says when it does not answer, and shows "N of M nodes unreachable" ("Node unreachable" for a single node). When the active node is down, its figures and charts are dimmed and show the age of the last sample.

The log keeps 5000 user and 500 polling requests and masks `api_key` and `value` secrets and the `x-typesense-api-key` query parameter. ⌘W / Ctrl+W closes a tab without disconnecting; ⌘⇧↩ / Ctrl+Shift+Enter zooms a tab.

Favorites also appear under "Collections" in the sidebar. Reload with ⌘R / Ctrl+R.

### Fixed

- The inspector and the update by query dialog mark a numeric string for a numeric field as an error instead of a warning: without `dirty_values` the server refuses `"12"` for an `int32`, so a warning hid a save that would fail. The import preview keeps the warning, because an import coerces by default.
- Document pages ignore curation sets, so a wildcard rule cannot hide or add rows in the browser and the found count matches what a delete or update by query reaches.
- Embedding credentials (`api_key` and similar) are masked in the schema view, the request log and "Copy as curl".
- A key that may read collections but not aliases still lists its collections; the list, the schema view and the delete dialog say inline that the aliases could not be loaded and why.
- A long truncate or delete no longer blocks the window: "Stop waiting" closes its dialog while the server keeps going, and the list reloads when it is done. A schema change, truncate or delete that hits the 30-minute timeout is not retried on another node and says the server may still be applying it.
- On read-only connections, the write controls (New collection, Edit schema, Clone, Truncate, Delete) show the lock until writes are unlocked.

### Changed

- The release profile aborts on panic (`panic = "abort"`), which keeps the Linux binary under the 40 MB limit (NF5).
- Profiles are stored in `connections.json` without keys; keys are stored in the OS keychain.
- The live tests use `http://localhost:18108` by default instead of port 8108. The dev server still starts on 8108 unless `TYPESENSE_PORT` is set.
